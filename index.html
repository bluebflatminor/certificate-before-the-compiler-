The Certificate Before the Compiler

A conformance schema for physical reservoir computing hardware

Solbakken Research Initiative · June 2026 · CC0 / public domain · v1.2
DRAFT — round-1 adversarial review + self red-team folded (records in README) — reference verification incomplete

Abstract

Physical reservoir computing has shipping hardware (an FPGA edge device with at least one industrial sale), funded corporate prototypes (analog and spintronic chips), and a mature software node-graph abstraction — but no layer connecting the two: any device can be wrapped in Python, yet no standardized characterization interface exists through which a photonic, memristive, spintronic, or nanowire reservoir can present itself to a common software framework. This note argues the missing layer is not a programming language or a compiler. Because the reservoir is fixed and only a linear readout is trained, the software contract is nearly trivial: three calls. What is missing is the characterization certificate a device must return for those calls to be meaningful — the measured properties that make readout training well-posed, hyperparameter transfer predictable, and benchmark claims comparable across devices. We propose a tiered schema with a stated evaluation order: a three-clause mandatory core — replica consistency, a noise floor derived from the full inter-channel covariance with a percentile-defined threshold, and ε-resolved effective dimensionality — plus three extended annex clauses. The core's binding principle is that correlated noise reduces honest dimensionality while remaining invisible to per-channel specifications; in dense, open, non-Hermitian devices its dominant instance is Petermann-type excess noise from mode non-orthogonality. A worked example on synthetic 200-channel reservoirs shows device pairs with identical per-channel noise power whose honest effective dimensionality differs severalfold: across ten realizations, 140–176 dimensions for the detector-limited device versus 31–42 for the correlated-noise device, with naive evaluation overstating the latter 3.4–3.8×. The magnitudes are properties of the toy; the structure of the failure is the claim. A falsification protocol and a conformance certificate are the same object read in opposite directions, and the schema is offered in that spirit, with its own kill condition stated (§10). The certificate, not the compiler, is the precondition for physical reservoir computing as a product category — a pre-normative standards object for which I found no evidence in current IEC TC 113 work items or VAMAS technical working areas.

1The gap: software without hardware semantics, hardware without contracts

The software side of reservoir computing (RC) is well served. ReservoirPy implements a computational graph of nodes — reservoirs, readouts, feedback connections — composed with an operator syntax and reduced internally to NumPy and SciPy operations [1]. Its designers are explicit that the graph machinery deliberately discards full differentiability: nothing is backpropagated through the reservoir, so no gradient-tape or compiler apparatus exists, because none is needed. PRCpy, more recently, provides a Python pipeline for post-processing experimental physical-reservoir data into readout-ready form [2]. On the hardware side, the one commercially sold reservoir device exposes a standalone gRPC client whose configuration surface is three scalars (a node bias, a memory gain, a node count) and whose output is a state matrix [3]. Corporate prototypes (analog electronic, spintronic) report task accuracies, not device properties.

Note what is absent. Any device can of course be wrapped in Python; what no device can do is register itself against a standardized characterization interface, because no shared definition exists of what a reservoir must report about itself before its states are trusted. PRCpy comes closest in spirit but is a data-processing pipeline, not an interface contract: it standardizes what you do with measurements after you have them, not what the device must certify before they mean anything. Each vendor's client is bespoke; each lab's characterization is ad hoc; no two published r_eff or memory-capacity numbers are measured under declared, comparable conditions.

2Why physical RC has no programming language — and is unlikely to need one

The absence of a language is structural, not an immaturity. In RC, learning is confined to a linear readout; the reservoir is a fixed dynamical system whose internal parameters are never addressed, written, or differentiated through [4, 5]. A programming language earns its existence when there is something in the substrate to address, route, schedule, or compile. Here, in the currently visible ecosystem, there is nothing: the entire programming model is (i) choose an operating point, (ii) stream inputs, (iii) regress on states. That maps exactly onto existing array libraries, which is why every stack in the field — academic and commercial — is Python over NumPy with at most a thin device client underneath. A future device class exposing rich in-substrate control would reopen the question — and would, by that very fact, be drifting out of reservoir computing.

The corollary is the thesis of this note. If the interface cannot carry programs, the only thing it can carry is claims — claims about dimensionality, memory, nonlinearity, noise, stability, and reproducibility. An interface that carries claims is a certificate. The engineering problem is therefore a metrology problem: specify the claims, pin the measurement protocols, and make the certificate machine-readable so that software can condition readout training on it.

3The interface: three calls

The logical minimum interface for a physical reservoir backend is three calls:

calibrate()  -> Certificate     # lock operating point, measure, certify
run(U)       -> X               # (T, n_in) input  -> (T, N) state matrix
report()     -> Certificate     # current certificate + drift since calibrate()

Real implementations will add reset, synchronization, streaming, buffer management, and encoder configuration; none of that moves where the content lives. Everything contentful is in the Certificate. A schema sketch (field names indicative, not final):

{
  "operating_point":  { "drive_power": ..., "bias": ..., "temperature": ...,
                        "input_ensembles": ["iid_uniform[-1,1]",

  "clause_5_consistency": {                          // CORE -- evaluate FIRST
      "replica_correlation": ...,

  "clause_2_noise": {                                // CORE -- evaluate SECOND
      "per_channel_psd": "...",

      "covariance_anisotropy_K_eff": 27.0,

      "eps_floor_percentile": 95,

      "N_readout": 200,

      "MC_curve": [[k, MC_k], ...],
      "tau_fading": ..., },

  "clause_4_nonlinearity": {                         // ANNEX
      "tier": 1,
      "linear_fraction": ..., "nonlinear_fraction": ...,
      "ipc_spectrum": null },                        // tier 2 optional

  "clause_6_disorder": {                             // ANNEX
      "disorder_statistics": "...",
      "transfer_class": "..." }
}

The input_transfer sub-block exists because the encoder — electro-optic modulator, spatial light modulator, DAC — has its own memory, drift, bandwidth, and cross-talk. If the input ensemble is filtered or distorted before it reaches the substrate, the certificate must say so, or every downstream clause inherits an unstated convolution. Core fields carry their own acquisition statistics — percentiles, run counts, ranges — because a certificate without repeatability statements is a spec sheet, not metrology.

4The clauses: a three-clause core, three annexes, one evaluation order

The schema is tiered, and the core has a mandatory evaluation order: Clause 5, then Clause 2, then Clause 1. The order is not bureaucratic. If the device fails consistency, the state matrix is not a reproducible object and every downstream measurement quantifies nothing stable; if the noise floor is not established, dimensionality is evaluated against an unknown baseline. Consistency gates noise, noise gates dimensionality. Clauses 3, 4, and 6 are extended annexes. A vendor unwilling to issue the core has nothing verifiable to sell; a vendor unable to issue the annexes has something to sell with stated limits. The tiering also reflects this note's own argumentative weight: the core is argued, the annexes are sketched, and hardening the annex protocols is precisely what the interlaboratory work of §9 exists to do.

Core · Clause 5 · evaluate first

Consistency and drift

The echo-state property cannot be proven from equations for a physical device; it must be measured. Report the replica-test consistency correlation — drive the device twice with the same input from different initial conditions and measure response convergence [10] — plus a drift specification: the validity interval of trained readout weights, temperature coefficients, and the recalibration trigger. This clause is core, not annex, for a structural reason: noise that enters inside the dynamics is processed by the same nonlinearity as the signal and is not separable from it by any spectral thresholding of the state matrix. The replica test is the instrument that sees dynamical noise. Clauses 2 and 1 are well-posed only on a device this clause has already passed.

Core · Clause 2 · binding

Noise floor, including correlated noise

Report the per-channel noise power spectral density and the inter-channel noise covariance matrix, from noise-only acquisitions at the certified operating point, and derive εfloor: a stated percentile (the worked example uses the 95th) of the rescaled largest noise singular value over a stated number of independent acquisitions (≥ 20). A single-realization threshold is not acceptable: the largest singular value of a finite-record noise matrix is a random variable with a fluctuating spectral edge, and a point estimate of a fluctuating maximum is not metrology. The binding principle is substrate-agnostic: correlated noise concentrates in specific state-space directions, raising the floor far above what per-channel power suggests, and no per-channel SNR specification can detect it. In dense, open, non-Hermitian devices — the regime the most computationally ambitious reservoirs inhabit — the dominant instance is Petermann-type excess noise from mode non-orthogonality [7, 12, 13]. For substrates far from that regime, the clause reduces to ordinary covariance bookkeeping at the cost of one extra measurement. That asymmetry is the point: the certificate does not assume the regime, it detects it. Scope, stated plainly: this clause's separation logic addresses noise additive at the readout chain (additive_noise_assumed is a schema field, not fine print); dynamical noise is Clause 5's province. Section 5 develops the photonic instance; Section 6 quantifies the failure mode.

Core · Clause 1 · evaluate third

Effective dimensionality, ε-resolved, two ensembles

Report not the readout channel count N but reff(ε): the number of singular values of the mean-centred state matrix exceeding ε · σmax, under a pinned input ensemble, drive power, and record length [6], evaluated only at ε ≥ εfloor. A scalar is meaningless because the quantity is ensemble- and power-dependent; the certificate reports the curve and pins both. Certification under a single ensemble invites tuning the operating point to the test, so the core requires at least two declared ensembles — an i.i.d. reference and a band-limited temporally correlated ensemble — with the difference between their reff curves reported as an input-sensitivity measure in its own right. Conformance tests of the form reff(· ; ε) ≥ rmin — or, as a kill condition, ≤ rmax — are instances of this clause.

Annex · Clause 3

Memory

Report the linear memory-capacity curve MC(k) [8] and a fading-memory timescale, measured at the same operating point as Clause 1, together with the valid input-bandwidth window: physical reservoirs have intrinsic timescales, and fading memory holds only inside a symbol-rate band the certificate must state explicitly.

Annex · Clause 4

Nonlinearity (tiered)

Tier 1: a Volterra-like linear/nonlinear variance split on a standard delayed-input sequence — cheap enough that every vendor can issue it. Tier 2: the full information-processing-capacity decomposition over polynomial degree [9], attractive because total IPC is bounded by the number of linearly independent state variables — a built-in cross-check on Clause 1 — and because it unifies memory and nonlinearity in one normalized spectrum. Tiering is deliberate: IPC is measurement-expensive, and a certificate no vendor can afford to issue is dead on arrival.

Annex · Clause 6

Disorder statistics and transferability

No two physical reservoirs are identical, so the certificate cannot promise weight portability — only that hyperparameters transfer predictably between devices of the same class. That requires reporting the device's disorder-field statistics: measure the disorder field first, then state the transfer class it implies. A transfer class is defined by statistical invariance, not pattern identity — individual disorder realizations differ, but the ensemble they are drawn from must match within stated tolerances: its covariance scaling laws, and, where a random-matrix description applies, the invariance of singular-value-spectrum statistics across devices. This clause is what separates a reproducible product category from a collection of artisanal one-offs.

5Clause 2 in depth: the excess-noise floor

The principle of Clause 2 is substrate-agnostic; this section develops its sharpest known instance. The standard practice — implicit in nearly every physical-RC paper — is to count dimensions down to whatever threshold the detection chain permits. For a closed, near-Hermitian system with independent per-channel noise this is defensible: the noise covariance is approximately σ²I, its singular spectrum is flat, and a floor estimated from per-channel power separates signal from noise directions.

An open cavity driven above transparency is not that system. Its modes are the eigenvectors of a non-Hermitian operator and are in general non-orthogonal; the projection of broadband fluctuations onto a non-orthogonal basis carries the Petermann excess factor, which grows with mode non-orthogonality and diverges toward exceptional points [7, 12, 13]. Two consequences matter for the certificate. First, the noise floor rises: εfloor scales with the largest singular value of the noise covariance, not with the per-channel power. Second, and less obviously, the excess noise is structured: it concentrates in the subspace spanned by the most non-orthogonal mode pairs, so the noise covariance is far from σ²I. A device characterized only by per-channel SNR will pass inspection while a substantial fraction of its claimed state space is noise-dominated.

This is precisely the regime in which a disordered open cavity must operate to be interesting as a reservoir: high effective dimensionality is purchased with mode density and openness, and mode density plus openness is what drives non-orthogonality. The excess-noise floor is therefore not a corner case but the generic operating condition of the most computationally ambitious physical reservoirs. The certificate clause that captures it — noise covariance, anisotropy, percentile floor — is the clause that does the real work.

6Worked example

Synthetic driven reservoirs (N = 200 channels, T = 4000 steps, tanh echo-state dynamics, spectral radius 0.9, i.i.d. uniform input; ten independent device realizations) are measured under two noise models with identical mean per-channel noise power (σ² = 4.0×10−4):

Case A — detector-limited: i.i.d. Gaussian noise, independent across channels. Case B — correlated noise: the same average power injected through a non-orthogonal mixing basis, giving a covariance anisotropy ratio Keff ≈ 27 (largest-to-mean eigenvalue of the noise covariance — analogous in role to a Petermann excess factor, though not constructed from mode non-orthogonality). Floors are percentile-defined per Clause 2: the 95th percentile of the rescaled largest noise singular value over 20 independent noise-only acquisitions. The single-file simulation (certificate_demo.py, NumPy only, fixed seeds) reproduces every number below.

Mean per-channel noise power4.0×10−44.0×10−4
Covariance anisotropy Keff≈ 127.0 [25.6, 29.6]
εfloor (p95, 20 acquisitions)0.0044 [0.0043, 0.0047]0.0192 [0.0184, 0.0213]

The two devices are indistinguishable on any per-channel specification. Their honest computational dimensionalities differ severalfold on every realization. The naive evaluation of Case B overstates its dimensionality 3.5× on average ([3.4, 3.8] across seeds) — the bulk of its apparent dimensions are noise. Only the covariance field of Clause 2 distinguishes the cases, which is the empirical content of the claim that the certificate, and specifically its noise-covariance clause, is load-bearing. The result also survived its own tightening: moving from a single-realization floor (v1.1) to the percentile definition left every headline quantity within its seed-to-seed spread. (A methodological echo: metrics validated under i.i.d. noise routinely die under correlated noise; assuming the former is how dimensionality claims in this field go wrong.)

What the toy does and does not show. It demonstrates that structured noise correlation degrades honest dimensionality and that per-channel specifications cannot detect this. It does not reproduce Petermann physics: the correlation structure of real excess noise is set by mode overlaps and gain profiles the toy does not contain, and its mixing matrix is a generic non-orthogonal basis, not a cavity's. The toy also certifies under a single input ensemble, where the schema requires two; the correlated-ensemble run is deferred with the rest of the upgrade path (§10): replacing the toy's mixing matrix with mode data from an open-boundary cavity simulation.

7The certificate predicts trainability

The certificate is not documentation; it is a pre-training predictor. Ridge regression on the state matrix is conditioned by the singular-value spectrum that Clause 1 reports: generalization is bounded by the number of state directions that stand above εfloor, and Clause 2 sets the minimum sensible regularization — a ridge parameter below the noise-implied scale fits structured noise by construction, and the resulting readout degrades on deployment. Clause 3's bandwidth window bounds the task class; Clause 5's validity interval bounds the deployment model. A purchaser can read achievable readout performance off the certificate before training a single weight. That — not vendor benchmarks on MNIST — is what would make physical reservoirs procurable.

8An instance in the wild: a kill condition as a Clause-1 test

The author's own speculative cavity-reservoir program (a plano-hemispherical disordered cavity, documented separately) carries the pre-registered kill condition reff(Nf = 50; ε) ≤ 50: if fifty frequency channels do not yield more than fifty effective dimensions, the architecture has no reason to exist. In the present vocabulary that is exactly a Clause-1 conformance test — and the analysis above says it is well-posed only on a device that has passed Clause 5, at an ε pinned at or above the Clause-2 percentile floor, measured with the noise covariance, not the per-channel power. A falsification protocol and a conformance certificate are the same object viewed from opposite sides: one is written to let a device fail, the other to let it pass, and both are empty without the metrology underneath.

9Standards positioning: a roadmap, not an announcement

The certificate is a pre-normative standards object. I found no evidence, in current IEC TC 113 work items or VAMAS technical working areas, of measurement protocols for ε-resolved dimensionality, noise covariance, memory capacity, or consistency in computing devices; existing nanotechnology specifications stop at materials classification, and photonic-integration metrology efforts target transceivers. That absence is unsurprising — most emerging device classes lack spec vocabulary — so the claim here is not the gap but the route through it: first, a shared open test suite implementing the three core clauses in software, runnable against any device exposing the three-call interface; second, an interlaboratory round robin on two dissimilar substrates, one photonic and one memristive — the natural VAMAS-style vehicle; third, draft vocabulary written from the round robin's discrepancies, which is where measurement vocabulary actually comes from.

One precondition is open and stated plainly: whether noise covariance, replica consistency, and ε-resolved rank can be measured comparably on a cavity, a crossbar, and a spintronic oscillator is itself unestablished. If they cannot, the certificate is not substrate-agnostic, and the schema degrades to per-substrate-class profiles — still useful, but a smaller claim. Whoever runs the round robin first defines the vocabulary the field's first real procurement contracts will use.

10What would make this note wrong

Four failure modes are stated in advance. (i) The clauses are the wrong set. If a property outside this schema routinely dominates device usability — the input-transfer sub-block exists because encoding nonidealities were the first identified candidate — the schema is incomplete and the framing fails. (ii) The correlated-noise clause is not binding in practice. If surveyed physical reservoirs operate with near-isotropic noise covariance (Keff ≈ 1 across photonic and non-photonic substrates alike), Clause 2 reduces to ordinary SNR and the note's central claim collapses to bookkeeping. The clause earns "binding" status only in dense, open, disordered regimes; whether commercially relevant reservoirs live there is an empirical question. (iii) The market never demands certification. Bilateral validation may simply outcompete certification, as it has repeatedly: GPUs for machine learning, FPGAs for high-frequency trading, and mining ASICs all matured on bilateral validation, with spec-sheet vocabulary arriving after the market rather than before. The certificate bets that physical RC differs because its value proposition is the certificate's contents — dynamical-systems properties rather than FLOPS — but that is an argument, not a fact. (iv) The certificate fails its own predictive test. The schema earns adoption only if its measured clauses predict task performance better than the existing ad hoc pair — per-channel SNR plus channel count. The §9 round robin is the venue: measure the clauses on two real reservoirs, predict trainability, compare against realized performance. If the certificate is not the better predictor, it is bookkeeping and should be discarded by its own standard.

The worked example is a toy by design: a tanh network with synthetic correlated noise demonstrates the logic of the clause structure, not the physics of any real cavity. The quantitative claims are properties of the toy's parameters, not of nature, and the toy certifies one input ensemble where the schema demands two. Replacing the toy with mode data from an open-boundary FDTD simulation of a real disordered-cavity geometry is the necessary next step before any of this is more than a schema proposal.
